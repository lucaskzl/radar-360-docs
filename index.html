■ Capítulo 01 — Contexto e Problema
🚨
Capítulo 01
Contexto Operacional e Problema Identificado

A Central de Atendimento de TI do INCRA, operada pela Positivo S+, enfrentava uma limitação crítica: a ausência de uma ferramenta centralizada que permitisse ao analista monitorar em tempo real o status de SLA (Service Level Agreement) dos chamados, acessar respostas padronizadas e registrar produtividade de maneira integrada. O sistema Cervello ESM não oferecia nativamente essa visibilidade operacional.

A Gerência de Suporte (GERTI/INCRA) demandava indicadores de desempenho mensais por analista. Identificou-se a necessidade de uma solução não-invasiva que não dependesse de acesso ao servidor, de APIs de terceiros ou de aprovação de TI para implantação.

Sintomas Identificados

✖
Chamados vencendo sem alerta visual ou sonoro ao analista responsável.
✖
Respostas redigidas do zero a cada atendimento, consumindo até 4 minutos por ticket.
✖
Ausência de indicadores de desempenho por turno.
✖
Contatos de gestores de sistemas dispersos, sem acesso ágil.
■ Capítulo 02 — Solução Desenvolvida
🚀
Capítulo 02
Solução Desenvolvida — RADAR 360

O RADAR 360 é um hub operacional integrado desenvolvido sob o paradigma de Extensão Nativa para Google Chrome. A solução atua como uma camada de inteligência e produtividade sobreposta ao sistema existente, oferecendo uma visão unificada e em tempo real de toda a operação de suporte.

Monitor SLA em Tempo Real

Integração via API REST com o backend Cervello, lendo e processando todos os chamados abertos a cada 10 segundos.

RPA de Respostas

Biblioteca de templates com preenchimento automático de dados do chamado (nome, ticket, CPF, login) via regex.

Mini-BI Operacional

Engine de telemetria que registra, agrega e apresenta dados de produtividade por analista e volume mensal.

■ Capítulo 03 — Stack Tecnológico
💻
Capítulo 03
Stack Tecnológico e Arquitetura
JavaScript ES6+
Linguagem principal. IIFE para encapsulamento de escopo, arrow functions e Optional Chaining. Estrutura não-invasiva ao código-fonte do Cervello.
Chrome Extension API
Ecossistema nativo do navegador. O script atua via Content Scripts injetados em document_idle, rodando com alta performance V8.
AJAX / REST API
O Motor V8 realiza chamadas ao endpoint reutilizando a sessão autenticada do analista.
Web Audio API
Geração de alertas sonoros via síntese de oscilador senoidal. Zero dependência de arquivos externos.
LocalStorage API
Persistência de dados (assinatura, tema, notas, produtividade) sem servidor próprio ou banco de dados externo.
CSS Design System
Tokens de cor via CSS Custom Properties. Sistema Bento Grid com suporte nativo a dark/light mode.
■ Capítulo 04 — Módulos e Arquitetura
🔌
Capítulo 04
Módulos e Arquitetura Funcional

A solução é estruturada em 13 módulos funcionais independentes, seguindo o princípio de responsabilidade única (SRP).

01 · Variáveis e Constantes

Configuração centralizada de cores, versão, coleções estáticas e estado global.

02 · Motor de Contexto

Extrai dados do chamado via regex e DOM traversal para preenchimento automático.

03 · Motor SLA V8

Processamento JSON, cálculo de SLA em minutos, categorização em buckets de criticidade.

04 · Radar Flutuante

Widget arrastável persistente com resumo do SLA visível em todas as páginas.

05 · RPA de Respostas

CRUD de templates com favoritos e injeção direta no editor Kendo.

06 · Auto-Save Inteligente

Listener de eventos DOM que registra produtividade do analista automaticamente.

07 · Mini-BI Mensal

Agregação de dados com exportação XLS nativa e relatório de turno.

08 · Interface Bento UI

Sistema de design proprietário com CSS Grid 12 colunas, glassmorphism e dark mode.
